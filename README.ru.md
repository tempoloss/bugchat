# bugchat — баг-чат в Telegram становится доской в Plane

Слушает чат, где люди жалуются, отсеивает болтовню и заводит остальное в
self-hosted [Plane](https://plane.so). Ответы в ветке становятся комментариями,
скриншоты — вложениями, а когда задачу закрывают, бот отвечает тому, кто её принёс.

[English version](README.md)

## Зачем он нужен

У Plane есть веб и мобильное приложение, поэтому бот, который умеет только создавать
задачи по команде, — это худшая версия и того, и другого. Здесь не про это.

Чего трекер не умеет — быть в комнате, где случилась жалоба. Люди сообщают о
проблемах в чате, обрывками, без заголовка, а потом продолжают разговор. Никто это
потом на доску не переносит, поэтому репорт не игнорируется, а **теряется**. Бот
живёт в этой комнате.

## Что делает

| В чате | В Plane |
|---|---|
| жалоба («не открывается», «500», «падает») или скриншот | задача в `Backlog`, метки `telegram` + `bug` |
| заявка («добавьте», «хотелось бы», «не хватает») | задача с меткой `feature`, приоритет `low` |
| «срочно», «критично», «прод лежит» | приоритет `urgent`; обычная жалоба — `high` |
| скриншоты | **встроены в описание**; файлы и видео — во вложения |
| альбом из нескольких скриншотов | **одна** задача со всеми картинками |
| ответ на сообщение, по которому уже есть задача | комментарий к этой задаче |
| правка исходного сообщения | описание обновляется |
| кнопка «🚫 Не баг», `/skip` или реакция 👎 | задача уезжает в `Cancelled` |
| «ок», «спасибо», «когда посмотрите?» | ничего |

На каждую задачу бот отвечает в чат — `🐞 OPS-12 · Backlog · high`, заголовок и
кнопка отмены в одно нажатие. У заявки иконка `💡`: автор сразу видит, как бот его
понял, и поправит тут же, а не через неделю на доске.

## Решения, которые имеют значение

Всё выше — обвязка. Ниже то, что имеет смысл забрать себе, и у каждого решения
написана его цена.

| решение | почему | детали |
|---|---|---|
| Серия сообщений от одного автора — один репорт | баг печатают обрывками, а не предложениями | [ADR 1](docs/adr/0001-a-burst-of-messages-is-one-report.md) |
| Сессионный логин вместо API-ключа | документированного эндпоинта может не быть в сборке | [ADR 2](docs/adr/0002-session-auth-not-an-api-key.md) |
| Короткий заголовок дополняется автором и временем | три задачи «не работает» неразличимы | [ADR 3](docs/adr/0003-a-short-title-is-not-a-title.md) |
| Заявка не бывает срочной | дай слову выставлять срочность — оно будет в каждой | [ADR 4](docs/adr/0004-a-request-is-never-urgent.md) |

### Один репорт — одна задача, а не три огрызка

Баг редко умещается в одно сообщение. «тут беда с реестром», потом «при выгрузке за
квартал», потом «вылетает 500» — это одна проблема, которую человек печатает, пока
думает. Разобранная по сообщениям, она превращается в три бесполезных обрубка.

Поэтому бот не триажит по сообщению. Он копит их по автору, ждёт
`BUGBOT_BURST_SECONDS` тишины от него и разбирает **всю серию разом**. Скриншоты из
этой же серии попадают в ту же задачу.

**Цена названа, а не спрятана:** ответ приходит примерно через двадцать секунд, а не
мгновенно. Это обмен, и `0` возвращает разбор по одному сообщению.

### Заголовки нормализуются, а короткие делаются различимыми

Первая строка сообщения — не заголовок. Снимаются обращения, вводные слова и крик,
уходят эмодзи и решётки, текст режется по концу первого предложения, результат
начинается с заглавной.

| В чате | На доске |
|---|---|
| `ребят, кароче не грузится список дел!!!` | Не грузится список дел |
| `не работает` + скриншот | Не работает — @someone, 03.08 10:26 |
| `при экспорте падает 500. воспроизводится каждый раз` | При экспорте падает 500 |

Интересна вторая строка. Слишком короткий заголовок дополняется автором и временем,
потому что три задачи «не работает» на доске неразличимы. Эту проблему видно после
первой недели работы, а не в момент написания парсера.

### Заявка не бывает срочной

У жалобы есть лексика. У заявки нет: «добавьте кнопку экспорта» не содержит
баг-слов и слишком коротка, чтобы пройти по длине, — такое сообщение раньше молча
пропадало между фильтром и доской.

Теперь есть второй словарь, и с ним два правила.

**Жалоба сильнее заявки в одном сообщении.** «Добавьте фильтр, а то выгрузка падает»
— это про падение. Завести такое низким приоритетом было бы прямо вредно.

**Заявка не бывает срочной**, даже «СРОЧНО добавьте выгрузку в pdf». Автор заявки
всегда считает её важной, и если срочность выставляется словом, через месяц вся
доска будет `urgent`. Просьба — не инцидент.

Прошедшее время в словарь заявок не входит нарочно: «добавили колонку» — это отчёт о
сделанном. Пропущенную заявку человек заведёт руками через `/task`, а ложная молча
засоряет доску, и это хуже.

## Установка

**1. Бот в Telegram.** Токен у [@BotFather](https://t.me/BotFather).

**Добавить в чат администратором.** Это не опция: privacy mode скрывает от ботов
обычные сообщения, а обновления о реакциях (👎 для отмены) приходят только админам.
Альтернатива для сообщений, но не для реакций — `/setprivacy` → `Disable`.

Id чата узнаётся так: запустить бота и написать в чат `/chatid`.

**2. Учётка Plane** с доступом к нужному проекту.

API-токена нет, потому что в self-hosted сборках его [могут просто
отключить](#сессионный-логин) — бот входит сессией, как браузер. Метки создаются
автоматически.

**3. Настроить и запустить:**

```bash
cp .env.example .env    # и заполнить
uv sync --python 3.12
uv run python -m bugbot
```

У `PLANE_BASE`, `PLANE_WORKSPACE` и `BUGBOT_PLANE_PROJECT` нет значений по умолчанию
нарочно: подставленный хост означает вход не туда, куда человек думает, поэтому бот
отказывается стартовать.

## Сессионный логин

<a id="сессионный-логин"></a>

Документированный путь автоматизации Plane — `/api/v1/` с `X-API-Key`. В
self-hosted сборках этого эндпоинта может не быть вовсе:
`/api/workspaces/{ws}/api-tokens/` отвечает 404, и выписать ключ негде. Поэтому бот
делает то же, что браузер:

1. `GET /auth/get-csrf-token/` — токен и кука `csrftoken`.
2. `POST /auth/sign-in/` с `csrfmiddlewaretoken`, `email`, `password`. Заголовки
   `Referer` и `Origin` **обязательны** — без них запрос не проходит проверку CSRF,
   и внятного сообщения об этом нет. Успех — **HTTP 302**, а не 200, и он ставит
   куку `session-id` на семь дней.
3. Внутренний `/api/...` с этой кукой. Записи требуют ещё `X-CSRFTOKEN`.

Если автоматизируете self-hosted Plane и упёрлись в ту же стену — читайте
`bugbot/plane.py`.

## Развёртывание

Docker Compose, состояние в именованном томе, `.env` только на хосте:

```bash
docker compose up -d --build
docker compose logs -f bugbot
```

`scripts/deploy.sh` пересобирает образ и ждёт строку готовности в логе, падая, если
она не появилась за минуту. Упавший логин в Plane иначе выглядел бы точно так же,
как успешная выкатка.

**Один инстанс на токен, не больше.** Два процесса, опрашивающих `getUpdates` с
одним токеном, дерутся, и Telegram отдаёт `409 Conflict` проигравшему. Локальную
копию перед выкаткой надо гасить.

## Команды

| Команда | Что делает |
|---|---|
| `/my` | все задачи, что ты завёл, с текущими статусами из Plane |
| `/task` 🔒 | ответом на сообщение — завести задачу, минуя фильтр |
| `/task 4` 🔒 | ответом на первое из четырёх — **одна** задача из всех четырёх |
| `/skip` | ответом — отменить задачу по этому сообщению; без ответа — последнюю |
| `/chatid` | id чата и слушается ли он |
| `/ping` | жив ли бот и куда пишет задачи |
| `/help` | краткая справка для коллег |

🔒 — только админы чата. `/task` обходит фильтр, то есть это самый простой способ
засыпать доску. Права спрашиваются на каждый вызов, поэтому снятый админ теряет
команду сразу, без перезапуска. Меню регистрируется по ролям: команды, которая
откажет по правам, в нём просто нет.

## Настройки

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `BUGBOT_BURST_SECONDS` | 20 | сколько тишины ждать, прежде чем считать серию автора законченной |
| `BUGBOT_MIN_TEXT_LEN` | 120 | длинное сообщение без баг-лексики всё равно заводит задачу |
| `BUGBOT_ALBUM_DEBOUNCE` | 2.0 | сколько ждать остальные части альбома, сек |
| `BUGBOT_MESSAGE_LOG_DAYS` | 7 | сколько помнить сообщения — нужно для `/task N` |
| `BUGBOT_POLL_TIMEOUT` | 25 | long-poll `getUpdates`, сек |
| `BUGBOT_MAX_ATTACHMENT_MB` | 20 | больше Bot API всё равно не отдаст |
| `BUGBOT_CLOSE_POLL_SECONDS` | 60 | как часто спрашивать Plane про закрытия; `0` — не отвечать |
| `BUGBOT_PLANE_STATE` | `Backlog` | состояние новых задач |
| `BUGBOT_PLANE_CANCEL_STATE` | `Cancelled` | куда уезжает отменённая |
| `BUGBOT_PLANE_LABELS` | `telegram` | метки на каждую задачу от бота |
| `BUGBOT_PLANE_BUG_LABEL` | `bug` | метка жалобы, вдобавок к общим |
| `BUGBOT_PLANE_FEATURE_LABEL` | `feature` | метка заявки |
| `PLANE_INSECURE` | не задан | `1` отключает проверку TLS; креды становятся уязвимы, лучше подложить CA |

Метки вида отделены от общих, и общий набор от них фильтруется, поэтому конфиг, в
котором осталось `telegram,bug`, не сделает заявку помеченной сразу и как баг, и как
заявка. Такое расхождение видно только глазами на доске.

Три словаря — жалобы, заявки и стоп-слова вида «починил» — живут в
`bugbot/triage.py` и покрыты тестами. Они русские, потому что таков чат, для которого
это писалось. Правьте регулярки и прогоняйте `pytest`.

## Тесты

```bash
uv run pytest -q
```

120 тестов, без сети. Часть с побочными эффектами — тонкая оболочка над чистой:
триаж, нормализация заголовков и перевод Plane-HTML в Telegram — чистые функции, так
что каждый путь проверяется без Telegram и без Plane.

`scripts/live_check.py` прогоняет настоящий путь против настоящего Plane с заглушкой
вместо Telegram: логин, метки, задача со скриншотом, комментарий, заявка с проверкой
метки и приоритета **по доске**, потом отмена. Полезно после смены пароля или
обновления Plane.

## Структура

```
bugbot/triage.py      жалоба, заявка или шум — чистая функция, вся логика
bugbot/plane.py       Plane через сессию: задачи, комментарии, метки, вложения
bugbot/plane_html.py  Plane HTML -> то немногое, что принимает Telegram
bugbot/telegram.py    Bot API
bugbot/store.py       SQLite: offset, «сообщение → задача», буферы альбомов и серий
bugbot/app.py         циклы и решения между ними
scripts/live_check.py настоящий путь против настоящего Plane, Telegram заглушен
docs/adr/             почему принято каждое несущее решение и чего оно стоит
```

## Известные ограничения

Задачи создаются одной сервисной учёткой, поэтому в Plane у всего один автор. `/my`
работает по Telegram-id отправителя, и задачи, заведённые до появления этой записи,
в списке не показываются.

Обычная группа — не супергруппа: у сообщений нет постоянных ссылок, поэтому в задаче
не будет ссылки на сообщение, а при апгрейде Telegram **меняет chat_id**. Бот
подхватит новый и напишет в лог, какой вписать в `.env`.

Удаление `state.db` забывает карту «сообщение → задача». Существующие задачи
останутся, но ответы в старых ветках перестанут превращаться в комментарии.
